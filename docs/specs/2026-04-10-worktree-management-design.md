# Worktree Management System — Design Spec

## Overview

A systematic worktree management system for the Umbraco Editor MCP server. Automates worktree lifecycle via Claude Code hooks, gives each worktree an isolated Umbraco instance (own database, own port), shows worktree context in the statusline, and cleans up fully on removal.

Also introduces gitflow with a `dev` branch as the integration branch.

## Gitflow Setup

- Create `dev` branch from `main`, push to origin
- `dev` is the integration branch — all feature branches merge here
- `main` is the release branch — only merged from `dev`
- Worktree create hook detects `dev` as the base branch (falls back to `main` if not found)
- Update CLAUDE.md to document this convention

## Components

### 1. Claude Code Hook Events

Register two hooks in `.claude/settings.json`:

```json
{
  "hooks": {
    "WorktreeCreate": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "bash \"$CLAUDE_PROJECT_DIR\"/scripts/worktree-create.sh",
            "timeout": 120
          }
        ]
      }
    ],
    "WorktreeRemove": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "bash \"$CLAUDE_PROJECT_DIR\"/scripts/worktree-remove.sh",
            "timeout": 30
          }
        ]
      }
    ]
  }
}
```

`$CLAUDE_PROJECT_DIR` always points to the main repo root, so scripts are found regardless of which worktree is active.

### 2. `scripts/worktree-create.sh`

**Input:** JSON on stdin: `{ "name": "<slug>", "cwd": "<project-root>" }`
**Output:** Worktree path on stdout (Claude Code uses this to set the working directory)

**Steps:**

1. **Parse input** — read name and cwd from JSON stdin
2. **Derive identifiers:**
   - Slug: the raw name (e.g. `restore-page`)
   - Directory slug: name with `/` replaced by `-` (e.g. `feature/foo` becomes `feature-foo`)
   - Branch name: names with `/` used as-is; names without `/` get `feature/` prefix
   - Worktree path: `$CLAUDE_PROJECT_DIR/.claude/worktrees/<directory-slug>`
   - Database name: `umbraco-mcp-editor-<directory-slug>`
3. **Detect base branch** — check for `dev`, fall back to `main`, then `master`
4. **Fetch latest** — `git fetch origin`
5. **Handle existing branches** — reuse local branch, track remote branch, or create new from base
6. **Create worktree** — `git worktree add <path> <branch>`
7. **Copy `.env`** — copy from main repo root to worktree root
8. **Create SQL Server database:**
   - Read SA password from main worktree's `demo-site/appsettings.local.json`
   - `docker exec sql bash -c '/opt/mssql-tools*/bin/sqlcmd -S localhost -U sa -P "<password>" -C -Q "CREATE DATABASE [<db-name>]"'`
9. **Write `demo-site/appsettings.local.json`** in the worktree:
   ```json
   {
     "ConnectionStrings": {
       "umbracoDbDSN": "Server=localhost,1433;Database=<db-name>;User Id=sa;password=<password>;TrustServerCertificate=True",
       "umbracoDbDSN_ProviderName": "Microsoft.Data.SqlClient"
     }
   }
   ```
10. **Rewrite `demo-site/Properties/launchSettings.json`** — change port to `0` for both HTTPS and HTTP URLs so dotnet binds to a random available port
11. **Ensure `.claude/worktrees/` is in `.gitignore`**
12. **Run `npm install`** in the worktree
13. **Output worktree path** on stdout

### 3. `scripts/worktree-remove.sh`

**Input:** JSON on stdin: `{ "worktree_path": "<absolute-path>" }`

**Steps:**

1. **Parse input** — extract worktree path
2. **Derive identifiers** — extract slug from path, derive database name
3. **Kill running demo-site** — find and kill any dotnet process running from this worktree's demo-site directory
4. **Drop database:**
   - Read SA password from main worktree's `demo-site/appsettings.local.json`
   - `docker exec sql bash -c '/opt/mssql-tools*/bin/sqlcmd -S localhost -U sa -P "<password>" -C -Q "DROP DATABASE IF EXISTS [<db-name>]"'`
5. **Remove worktree** — `git worktree remove --force <path>`
6. **Fallback cleanup** — if remove fails (locked files), run `git worktree prune` then `rm -rf <path>`

### 4. `.worktreeinclude`

```
# Environment config (API credentials for MCP tools)
.env
```

Only `.env` needs copying. The demo-site is committed in the repo (already present in worktrees). `appsettings.local.json` is generated by the create hook with the worktree-specific database name.

Processed using: `git ls-files --others --ignored --exclude-from=.worktreeinclude` then bulk-copied via `tar`.

### 5. Port Management

**Main worktree:** Keeps its fixed port (44386) in `launchSettings.json`. No changes to existing workflow.

**Worktrees:** The create hook rewrites `launchSettings.json` to use port 0:
```json
{
  "profiles": {
    "Umbraco.Web.UI": {
      "applicationUrl": "https://localhost:0;http://localhost:0"
    }
  }
}
```

When `dotnet run` starts, .NET Core binds to a random available port. The `start-umbraco.sh` script is enhanced to:
1. Run `dotnet run` and capture output
2. Parse the bound port from the "Now listening on: https://localhost:XXXXX" log line
3. Write the port to `.demo-site-port` in the project root
4. Update `UMBRACO_BASE_URL` in the worktree's `.env` to match

A helper script `scripts/get-demo-site-url.sh` reads `.demo-site-port` and returns the URL. This is used by the statusline and can be used by the MCP inspect command.

### 6. Statusline

Update the statusline command in `.claude/settings.local.json` to show:

```
worktree: restore-page | branch: feature/restore-page | umbraco: :44401
```

The statusline reads:
- Worktree name from the worktree path
- Branch from `git rev-parse --abbrev-ref HEAD`
- Umbraco port from `.demo-site-port` (if file exists and demo-site is running)

### 7. CLAUDE.md Updates

Add/update the Git Worktrees section to document:

```markdown
## Git Worktrees

This project uses git worktrees for feature work. Use `EnterWorktree` to
create or enter a worktree — hooks handle everything automatically:

- `.env` is copied from the main repo
- A new SQL Server database is created (named `umbraco-mcp-editor-<slug>`)
- `demo-site/launchSettings.json` is rewritten to use a dynamic port
- `npm install` runs automatically
- First `dotnet run` triggers Umbraco unattended install in the new database

### Gitflow

- `dev` — integration branch, all feature branches merge here
- `main` — release branch, only merged from `dev`
- Feature branches: `feature/<name>` (auto-prefixed by worktree hook)

### Running the demo site in a worktree

`npm run start:umbraco` — starts Umbraco on a random port. The port is
written to `.demo-site-port` and `UMBRACO_BASE_URL` in `.env` is updated.

### Cleanup

Use `ExitWorktree` with remove action, or the `/cleanup` skill.
The hook drops the worktree database and removes the worktree directory.
```

### 8. .gitignore Updates

Ensure these entries exist:

```
.claude/worktrees/
.demo-site-port
```

The existing `.worktrees` entry should be replaced with `.claude/worktrees/` for correctness.

## Database Naming Convention

| Context | Database Name |
|---------|--------------|
| Main worktree | `umbraco-cms-editor-mcp` (existing, unchanged) |
| Worktree `restore-page` | `umbraco-mcp-editor-restore-page` |
| Worktree `feature/ideas` | `umbraco-mcp-editor-feature-ideas` |
| PR checkout `fix/bug-123` | `umbraco-mcp-editor-fix-bug-123` |

Pattern: `umbraco-mcp-editor-<slug>` where slug is the worktree directory name (branch `/` replaced with `-`).

## What Happens End-to-End

### Creating a worktree

```
User: "Create a worktree for restore-page"
Claude: calls EnterWorktree with name "restore-page"
→ Hook fires: scripts/worktree-create.sh
  → Creates .claude/worktrees/restore-page/ on branch feature/restore-page from dev
  → Copies .env
  → Creates database umbraco-mcp-editor-restore-page
  → Writes demo-site/appsettings.local.json with connection string
  → Rewrites launchSettings.json to port 0
  → Runs npm install
  → Outputs worktree path
→ Claude Code sets working directory to the worktree
→ Statusline shows: worktree: restore-page | branch: feature/restore-page
```

### Running Umbraco in the worktree

```
User: "Start umbraco"
Claude: runs npm run start:umbraco
→ dotnet run binds to random port (e.g. 44401)
→ start-umbraco.sh captures port, writes .demo-site-port
→ Updates .env with UMBRACO_BASE_URL=https://localhost:44401
→ Umbraco unattended install runs (first time only), creates schema in new DB
→ Statusline shows: worktree: restore-page | branch: feature/restore-page | umbraco: :44401
```

### Cleaning up

```
User: "Clean up this worktree"
Claude: calls ExitWorktree with remove action
→ Hook fires: scripts/worktree-remove.sh
  → Kills dotnet process
  → Drops database umbraco-mcp-editor-restore-page
  → Removes .claude/worktrees/restore-page/
  → Prunes git worktree refs
→ Claude Code returns to main worktree
→ Statusline shows: worktree: main worktree | branch: dev
```
